Research Paper & Specification

SATE AI: Systematic Fault Injection Framework for On-Device AI Models in Flutter

Antigravity & SATE AI Research Team

Status: Preprint (arXiv submission pending)

Download PDF Paper Download LaTeX Source (.tex) Download BibTeX (.bib)

Abstract / Summary

Deploying quantized neural networks and large language models (LLMs) on consumer edge and mobile devices subjects inference pipelines to volatile runtime conditions: memory pressure, dynamic thermal throttling, quantization drift, unvalidated user inputs, and sensor data corruptions. Existing mobile testing paradigms lack specialized fault injection mechanisms tailored for AI inference runtimes.

We present SATE AI, a cross-platform fault injection and reliability engineering framework across Flutter, Dart, Android Native (Kotlin), and Web/Node.js (TypeScript) ecosystems. SATE AI evaluates model robustness across 12 domain-specific failure modes and 8 inference adapters. We evaluate SATE AI across four production model architectures (MobileNetV2 TFLite INT8, MobileNetV2 ONNX FP32, ResNet-18 ONNX FP16, and SmolLM-135M GGUF Q4) deployed on physical ARM64 smartphone hardware (TECNO CH7n, MediaTek Helio G85, 8GB RAM, Android 12). SATE AI reveals latency expansions of up to 4.8x under thermal throttling, uncovers unhandled OOM terminations under 800MB heap pressure, and proves that closed-loop adaptive chaos sustains peak stress without triggering unrecoverable kernel process evictions.

1. Software Architecture

SATE AI enforces a decoupled architecture isolating fault injectors, model adapters, and orchestration runners. This allows model runtimes (such as ONNX Runtime, TensorFlow Lite, Fllama/llama.cpp, MediaPipe, Core ML, and Google ML Kit) to be evaluated under simulated stress scenarios without modifying the core model execution engine.

Figure 1: SATE AI Architecture showing core components, adapters, and fault injectors.

The framework features 12 fault injectors capable of targeting memory pressure, thermal degradation, quantization drift, latency spikes, input corruption, model swapping, confidence validation, network latency drops, GPU memory pressure, data corruption, version mismatches, and adaptive chaos injection modulated by live device telemetry.

3. Fault Injection Workflow & Closed-Loop Telemetry

During stress execution, the StressRunner coordinates sequential or grouped fault injections against an AIModelAdapter instance. The AdaptiveChaosInjector continuously queries real-time device telemetry (CPU frequency, available RAM headroom, and junction temperatures via ThermalService), modulating injection pacing according to:

Δt_k = Δt_base × max(α_min, [M_headroom(t) / M_budget] × [1 - ((T(t) - T_baseline) / (T_crit - T_baseline))^2])
